# T3 tables

T1 (entities) and T2 (edges) are extracted from the CodeQL database and state
only what a syntactic query sees in the source. T3 holds the dependencies
that need judgement to establish, and that wavefront does not infer:

- a type-erased value (`void *`, `void **`) handed on through calls or
  locals. `av_log(void *avcl)` only passes `avcl` to `av_vlog`, whose body
  reads it as `AVClass`. Wavefront records that cast at `av_vlog` alone, so
  without T3 `av_log` does not depend on AVClass;
- a polymorphic pair joined through such slots;
- which type-minting macros are templates (`GIT_HASHMAP_STRUCT`, minting 24
  same-shaped maps) rather than one-off definitions (`FF_PAD_STRUCTURE`);
- which cast edges wavefront derives are no polymorphism: an alignment pun
  (`AVPacket.data` read as `union unaligned_32` by `AV_RN32`), or a slot one
  file reuses (`AVStream.priv_data` holding an `AVPacket` in `flacenc.c`).

`chased_casts.csv` rows therefore have an `op`: `add` states an edge
wavefront misses, `drop` removes one it derives.

The tables live in the config's `t3_dir`, relative to `state_dir`, and are
tracked with the campaign. Without `t3_dir` there is no third tier and no
macro is a generator.

## Format

Same conventions as T1/T2: one CSV per relation, a header row, snake_case
columns, repository-relative paths, `""` where a column does not apply,
`<role>_name` + `<role>_def_file` per entity. Rows are an unordered set;
duplicates merge.

### `chased_casts.csv`

| column | meaning |
|---|---|
| `kind` | `erased_arg` \| `erased_field` \| `base_derived` |
| `slot_name` | the function (`erased_arg`) or the owner struct (`erased_field`); `""` for `base_derived` |
| `slot_def_file` | its definition file |
| `slot_member` | the 0-based parameter position, or the field path as `t1/fields.csv` spells it (`data.odb` for a member of an anonymous aggregate; `in.p` through a tagged embedded struct resolves to that struct's own field) |
| `type_name`, `type_def_file` | the type the slot holds (`erased_arg`, `erased_field`), or the base of a pair (`base_derived`); `base_name`, `base_def_file` in a header are read as these |
| `derived_name`, `derived_def_file` | `base_derived` only |
| `op` | `add` \| `drop`; `""`, or a header without the column, is `add` |

```csv
kind,slot_name,slot_def_file,slot_member,type_name,type_def_file,derived_name,derived_def_file,op
erased_arg,av_log,libavutil/log.c,0,AVClass,libavutil/log.h,,,add
erased_field,Holder,src/holder.h,opaque,Payload,src/payload.h,,,add
base_derived,,,,AVClass,libavutil/log.h,AVCodecContext,libavcodec/avcodec.h,add
erased_field,AVPacket,libavcodec/packet.h,data,unaligned_32,libavutil/intreadwrite.h,,,drop
erased_field,AVStream,libavformat/avformat.h,priv_data,AVPacket,libavcodec/packet.h,,,drop
```

### `type_generators.csv`

| column | meaning |
|---|---|
| `generator_macro`, `generator_def_file` | the macro and the file of its `#define` |
| `derived_kind` | `type` (an instance it mints) \| `macro` (a macro it expands into a family of its own) |
| `derived_name`, `derived_def_file` | the instance type or the macro |

A `type` row has the columns of `t2/macro_generated_types.csv`, the
extracted record of which invocation minted which type.

## Row meaning

What each row states, as an edge of the graph (`A -> B`: A needs B first).
How these edges join, and are pruned in an API graph, is in
[`graph.md`](../graph.md#type-erasure).

| row | `add` | `drop` |
|---|---|---|
| `erased_arg` | the function depends on `type`, as on a typed parameter | the function no longer depends on `type` through that parameter's body read |
| `erased_field` | `type`, an instance of the owner, depends on the owner | `type` is no variant of that field |
| `base_derived` | `derived -> type`, replacing the written cast edge between them | no cast edge between the two, in either direction |
| generator, `type` | the instance depends on the macro, which `generates` it | |
| generator, `macro` | the derived macro depends on the generator | |

A `drop` row removes only an edge wavefront derives from T2: a parameter's
body read, a field's variant, or a cast pair. A `drop` of an edge wavefront
does not derive, or an `add` of a body read or variant it already derives,
is stale, and is reported as a warning when the graph is built.

## Checks

Rows are checked when loaded. Every failing row is listed, by file and line,
and the command stops; a row is never skipped.

- Columns: present (`op` may be absent); `kind` / `derived_kind` / `op`
  known; the columns a kind needs filled, the others empty; no edge both
  added and dropped.
- Types: `(name, def_file)` is an entity in `t1/types.csv` (a type with a
  definition is named by its defining file); base and derived differ.
- `erased_arg`: the function is in `t1/functions.csv` at `slot_def_file`,
  the position exists, and `t1/params.csv` marks it `is_erased`.
- `erased_field`: the owner exists, the field path is in `t1/fields.csv`, and
  it is `is_erased` or a scalar pointer (`uint8_t *data`), the fields
  wavefront records variants for.
- Generators: the macro is in `t1/macros.csv` at `generator_def_file`; the
  derived type or macro exists; a macro does not generate itself.

The checks are the same in every mode.

Not checked: the relation itself -- that the value really travels from the
slot to the cast, or that a macro is a template. That judgement is what the
tier records.
